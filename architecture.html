Architecture

From the field to a sealed record.

The technical layout of the SABAGeo Web-GIS platform: how survey data travels from the field, through a PostgreSQL/PostGIS database, to a tamper-evident record on the Polygon network.

How to read this page

Every part of the design carries a label, so you can see what already works and what is still to come.

Built works in the prototype today. Test network works, on Polygon's test network. Planned designed, not built yet.

1. Introduction and overview

Real-time field validation improves how survey data is checked. Technical users query an open-source PostgreSQL/PostGIS database through a custom API, and the database makes the key decision itself: does this new parcel overlap land that is already registered?

Once a plot is verified, the system creates a unique SHA-256 fingerprint of the record. In the full design, a smart contract writes that fingerprint onto the Polygon network, so citizens, corporate developers and land lenders can verify boundaries through a public mobile app.

In the prototype, the overlap check, the fingerprint and the posting to Polygon's test network work. The smart contract and the mobile app are planned.

4. Programmatic spatial checks

The core checks run inside PostgreSQL/PostGIS, so tech officers can analyse space without desktop drafting software.

ST_Intersects finds parcels that touch or share area with the new one, to prevent double titling. The shared area is then measured and shaded on the map, with its size, its centre and the plot it hits. Plots that only touch along a boundary are not counted, and neither are slivers thinner than 10 cm, which come from rounding.Built
ST_Contains checks that a survey plot lies inside a valid government land zone. It needs a table of approved zones, for example the NAUB staff quarters boundary.Planned

The database tables today

  • plots: every parcel, with its title code, region, shape (WGS84), area, source and DISJOINT or ADJOINING tag.
  • regions: the localized datasets, the NAUB pilot with its reserved slots, and a test area.
  • ledger: the hash chain, where each record carries the fingerprint of the one before it.
  • photos: geotagged beacon photos and their distance from the plot.
  • anchors: ledger fingerprints posted on Polygon.

Only the fingerprint goes on the blockchain. The parcel data itself stays in the database.
